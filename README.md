# DiaboliX

Локальная оболочка для работы с OpenAI-совместимыми моделями. LangGraph управляет последовательностью: планировщик, исполнитель с инструментами и рецензент. Планировщик и рецензент автоматически вызывают ту же модель и не имеют инструментов; они не проверяют файлы самостоятельно. Вызовы специалистов увеличивают расход токенов и задержку.

## Запуск

Нужны Node.js 20+, Docker Engine или Docker Desktop и доступ пользователя к Docker. В каталоге проекта:

```sh
npm install
docker build -t diabolix-sandbox:local sandbox
npm start
```

Откройте [http://localhost:6660](http://localhost:6660). Укажите OpenAI-совместимый endpoint, ключ при необходимости, модель и абсолютный путь к проекту. Поиск моделей использует `/models`, а работа агента — `/chat/completions` с вызовами инструментов. Для локального API укажите его адрес так, как он доступен с компьютера, где запущен Node.js. Ключ и история остаются только в памяти процесса.

## Изоляция

Сервер интерфейса и запросы к провайдеру работают на хосте. Каждый встроенный инструмент выполняется в отдельном краткоживущем Docker-контейнере без сетевого доступа и Docker socket, с непривилегированным пользователем, read-only корневой файловой системой, ограничениями CPU, памяти и числа процессов. Выбранный проект монтируется на запись в `/workspace`: изменения в нём затрагивают реальные файлы на хосте. Не выбирайте домашний каталог целиком и не храните секреты в выбранной папке. В контейнере нет сети, поэтому установка пакетов и работа с удалённой инфраструктурой из команд недоступны. Контейнер не заменяет полноценную виртуальную машину; безопасность зависит от Docker и хоста. На Linux могут потребоваться права записи UID 1000 в выбранной папке. При недоступном Docker или отсутствии образа инструменты возвращают ошибку и не выполняются на хосте.

Изоляция указывается в системном промпте каждого вызова модели. При остановке или тайм-ауте контейнер принудительно удаляется. Провайдер получает задачу и содержимое результатов инструментов, поэтому выбирайте доверенного провайдера.

## MCP

Необязательно укажите URL доверенного MCP-сервера с транспортом Streamable HTTP в настройках. Официальный MCP SDK обнаруживает его инструменты и позволяет модели вызывать их. **MCP-инструменты выполняются на самом MCP-сервере, вне локальной Docker-песочницы**, и могут иметь доступ к сети, файлам или другим ресурсам согласно настройкам этого сервера. Данные аргументов отправляются MCP-серверу. Поддержки авторизации MCP и stdio-подключений пока нет. Оставьте поле пустым, чтобы отключить MCP.

## Ограничения

Это начальная реализация harness: нет долговременной истории, утверждения команд, автоматического исправления замечаний рецензента или полноценной песочницы для сторонних MCP-серверов. CrewAI, Pydantic AI и AutoGen не подключены; вместо смешивания Python-фреймворков используется LangGraph для Node.js.

## Планирование, AST и откат

Планировщик использует ограниченный MCTS: до двух предложенных моделью вариантов и четыре оценочных симуляции с выбором по UCB. Это оценки модели, а не реальные прогоны кода; они добавляют запросы и стоимость. При некорректном ответе планировщика используется полученный текст без поиска.

Инструмент `parse_ast` разбирает JavaScript/JSX и Python в песочнице и возвращает до 300 объявлений и импортов. Для `index_graph` задайте переменные `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`, при необходимости `NEO4J_DATABASE` перед запуском сервера. Он сохраняет узел файла и его AST-элементы с отношениями `CONTAINS`; это индекс символов, а не полный граф межфайловых зависимостей. Данные выбранного файла отправляются в указанную Neo4j. Доступ к базе осуществляется сервером на хосте, а не контейнером.

Агенту предписано запускать тесты до и после изменений через `run_tests`. Перед записью файла или выполнением shell-команды требуется запустить базовую проверку через `run_tests`; после изменений агент должен добиться успешного `run_tests` или явно сообщить о блокирующей причине через `report_test_blocker`. Это контролирует последовательность встроенных инструментов, но не проверяет качество выбранной тестовой команды и не ограничивает внешние MCP-инструменты. Агент может вызвать `rollback_last_write`: он отменяет последнюю запись `write_file` текущей задачи при совпадении содержимого с результатом записи. Точки отката хранятся в памяти, только для файлов до 1 МБ, и исчезают после задачи; изменения shell-команд, MCP и Neo4j они не откатывают. Для полноценного восстановления используйте контроль версий и резервные копии.
